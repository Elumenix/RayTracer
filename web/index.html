Documentation of how to use the code editor. Select a section below to explore its properties and examples.

This application uses YAML (YAML Ain't Markup Language), a human-readable data format, as input to the RayTracer. A scene consists of a list of objects and reusable definitions, including shapes, cameras, lights, materials, transforms, and patterns.

YAML lists of objects use hyphens (-) to start each entry, followed by indented key-value pairs that define its properties. Each hyphen represents a new entry, and properties belonging to that entry must be indented consistently.

Tip: Lists can also be written using square brackets to keep values on a single line. For example, color: [0, 0.2, 0] defines a list of three values. This notation is commonly used for properties such as colors, positions, and vectors.

Indentation also determines how properties are grouped together. Properties indented beneath another property belong to it, allowing you to define nested structures. This is particularly useful when defining materials, patterns, and transforms.

Property names must match those expected by the RayTracer. While YAML allows you to use different names, the RayTracer will only recognize supported properties.

Below is an example of a starter scene containing a camera, a light source, and a sphere: 

- add: camera
  width: 512
  height: 512
  field-of-view: 1.0472

- add: light
  at: [0, 5, 0]
  intensity: [1, 1, 1]

- add: sphere
  material:
  transform:
    - [translate, 0, 0, -3]
Important: A scene must contain exactly one camera in order to render.

The camera controls the viewpoint and resolution of the generated image. Every scene must contain exactly one camera.

The width, height, and field-of-view properties are required. All other properties are optional and will use their default values if omitted.

Properties
Property Description Required Default Valid Values / Constraints
width Image width in pixels Yes — Greater than 0
height Image height in pixels Yes — Greater than 0
field-of-view Field of view in radians Yes — Greater than 0 and less than 2π
reflection-depth Maximum number of ray bounces No 5 0 or greater
from Camera position No [0, 0, -5] 3D vector
to Look-at position No [0, 0, 0] 3D vector
up Camera up vector No [0, 1, 0] 3D vector
Performance Note: Image resolution (width and height) and reflection depth (reflection-depth) can significantly affect rendering time. Higher values generally result in longer render times.
Example

The following example defines a camera using only the required properties. All optional properties will use their default values. 

- add: camera
  width: 512
  height: 512
  field-of-view: 1.0472

You can also explicitly specify optional properties to customize the camera: 

- add: camera
  width: 512
  height: 512
  field-of-view: 1.0472
  from: [0, 0, -5]
  to: [0, 0, 0]
  up: [0, 1, 0]
Important: The up vector must be non-zero and must not be parallel to the camera's viewing direction (the direction from from to to). Otherwise, the camera orientation cannot be calculated.

A point light emits light in all directions from a single position in the scene. It illuminates objects and allows them to cast shadows.

Properties
Property Description Required Default Valid Values / Constraints
at Position of the light in world space Yes — 3D vector
intensity RGB light intensity (color) Yes — RGB vector
Tip: Adding at least one light to your scene is recommended. Without sufficient lighting, objects may appear very dark or not be visible at all.
Performance Note: Each additional light increases the amount of work required during rendering and may increase rendering time, particularly in complex scenes.
Important: Placing a light inside an object will likely prevent its light from escaping, regardless of the object's material. Position lights outside of objects to ensure their illumination reaches the rest of the scene.
Example

The following example defines a white light positioned at the origin: 

- add: light
  at: [0, 0, 0]
  intensity: [1, 1, 1]

The RayTracer supports three basic geometric shapes: planes, spheres, and cubes. All three use the same properties to define their appearance and positioning.

Shapes
  • Sphere: A three-dimensional ball.
  • Cube: A three-dimensional box with equal sides.
  • Plane: A flat, infinite surface.
Properties
Property Description Required Default Valid Values / Constraints
material Defines the surface appearance Yes (empty = default) Default material Material definition
transform Defines the shape's position, orientation, and scale Yes (empty = default) Identity transform Transform definition
Tip: Materials and transforms have their own properties and can be customized independently. See the Materials and Transforms sections for more information.
Example

The following example creates a red sphere and moves it three units along the negative Z-axis: 

- add: sphere
  material:
    color: [1, 0, 0]
  transform:
    - [translate, 0, 0, -3]

Materials determine how an object's surface interacts with light, controlling its color, shading, reflectivity, and transparency. Materials can also use patterns to create more complex surface appearances.

Properties
Property Description Required Default Valid Values / Constraints
color Base color of the material No* [1, 1, 1] RGB vector
pattern Defines a pattern applied to the object's surface No* None Pattern definition
ambient Controls how much the surface is illuminated independently of direct lighting No 0.1 Between 0 and 1
diffuse Controls how much the surface scatters light in different directions No 0.9 Between 0 and 1
specular Controls the brightness of specular highlights No 0.9 Between 0 and 1
shininess Controls the size and sharpness of specular highlights No 200 0 or greater
reflective Controls how much the surface reflects light No 0 Between 0 and 1
transparency Controls how much light passes through the surface No 0 Between 0 and 1
refractive-index Determines how much light bends when passing through the material No 1 0 or greater
Tip: All material properties are optional and will use their default values if omitted. This allows you to customize only the properties you need.
Important: A material can define either color or pattern, but never both. If neither is specified, the material will use its default white color.
Example

The following example creates a red material with reduced diffuse lighting and increased reflectivity: 

material:
  color: [1, 0, 0]
  diffuse: 0.5
  reflective: 0.5

You can also define a pattern instead of a color: 

material:
  pattern:
    type: stripes
    colors:
      - [0, 0, 0]
      - [1, 1, 1]
Tip: See the Patterns section for more information about available pattern types and their properties. Materials can also be defined and reused across multiple objects. See the Definitions section for more information.

Patterns define how a material's appearance varies across an object's surface. They can be used to create procedural designs using colors or combinations of other patterns.

Patterns are assigned to a material using the pattern property in place of color. Each pattern requires a type and a list of colors or child patterns.

Pattern Types
Type Description
checkers Creates a checkerboard pattern.
stripes Creates alternating stripes.
gradient Creates a gradual transition between colors.
ring Creates concentric rings.
radial Creates a radial gradint ring.
blend Combines two colors or child patterns.
perturb Distorts another pattern using perlin noise.
Properties
Property Description Required Default Valid Values / Constraints
type Determines the type of pattern Yes — Supported pattern type
colors Colors or child patterns used to create the pattern
Requires 2 entries / 1 entry (perturb only). 		Yes — RGB vector or Pattern definition
seed Determines the random seed used for pattern distortion
Only affects perturb 		No 1337 Integer
strength Controls the amount of distortion applied to the pattern
Only affects perturb 		No 0.3 Numeric value
transform Controls the position, rotation, and scale of the pattern No Identity transform Transform definition
Tip: The order of entries in colors matters. Each entry can be either an RGB color or a child pattern, allowing patterns to be combined.
Tip: The seed and strength properties only affect perturb patterns. If omitted, they default to 1337 and 0.3, respectively. It is recommended to keep strength below 1 for a subtle distortion.
Important: All patterns except perturb require exactly two entries in colors. Perturb patterns require exactly one entry, which defines the pattern being distorted.
Example

The following example creates a striped pattern using black and white: 

material:
  pattern:
    type: stripes
    colors:
      - [0, 0, 0]
      - [1, 1, 1]

Patterns can also use previously defined patterns as their colors. The following example defines a striped pattern and then uses it as the input for a perturb pattern: 

- define: stripes-pattern
  value:
    type: stripes
    colors:
      - [0, 0, 0]
      - [1, 1, 1]

- add: cube
  material:
    pattern:
      type: perturb
      colors:
        - stripes-pattern
      seed: 1337
      strength: 0.3
  transform:
Tip: Transforms can also be applied to patterns independently of their objects, allowing you to adjust the position, rotation, and scale of a pattern without changing the object's transformation. See the Transforms section for more information.

Transforms determine the position, orientation, and scale of an object in the scene. They can be used to move, rotate, resize, and distort objects using a sequence of transformation operations.

Transforms are assigned using the transform property and consist of a list of operations. Each operation is applied in the order it appears in the list.

Transformation Operations
Operation Description Format
translate Moves the object along the X, Y, and Z axes. [translate, x, y, z]
scale Multiplies the object's size along the X, Y, and Z axes. [scale, x, y, z]
rotate-x Rotates the object around the world's X axis. [rotate-x, radians]
rotate-y Rotates the object around the world's Y axis. [rotate-y, radians]
rotate-z Rotates the object around the world's Z axis. [rotate-z, radians]
shear Skews the object along the specified axes. [shear, xy, xz, yx, yz, zx, zy]
Tip: Translation and scaling operations require three numeric values, one for each axis. Rotation operations require a single numeric value representing the rotation angle in radians. Shearing requires six numeric values, representing the shear factors between the axes.
Important: The order of transformation operations matters. Each operation is applied in sequence, so changing their order can produce a different result. Rotations are performed around the world's axes.
Example

The following example scales an object to twice its original size, rotates it 45 degrees around the Y axis, and then moves it along the Y and negative Z axes: 

transform:
  - [scale, 2, 2, 2]
  - [rotate-y, 0.7854]
  - [translate, 0, 1, -3]

Transforms can also be defined and reused across multiple objects. This is useful when several objects need to share related positioning, rotation, or scaling operations. 

- define: shared-transform
  value:
  - [scale, 1.5, 1.5, 1.5]
  - [translate, 2, 0, 5]

- add: cube
  material: 
  transform: shared-transform

- add: cube 
  material: 
  transform: 
  - shared-transform
  - [translate, -4, 0, 0]
Info: Transforms can also be extended (See Definitions). In practice, this behaves identically to the above example of putting the definition in the transform list, making it less preferred.

Definitions allow you to create reusable configurations for materials, patterns, and transforms. They help reduce repetition and make it easier to maintain consistent properties across multiple objects.

Definitions are created using the define property and can be referenced by name wherever the corresponding configuration is supported.

Properties
Property Description Required Default Valid Values / Constraints
value The properties that make up this definition Yes — Material, pattern, or transform definition
extend Name of the existing definition to inherit properties from No None Name of an existing definition
Example

The following example defines a red material with reduced diffuse lighting: 

- define: red-material
  value: 
    color: [1, 0, 0] 
    diffuse: 0.9

Once defined, the material can be referenced by name when assigning materials to objects: 

- add: sphere
  material: red-material 
  transform:
    - [translate, 0, 0, -3]
Tip: Definitions can be referenced by multiple objects, allowing them to share the same material, pattern, or transform configuration without repeating its properties.
Extending Definitions

Existing definitions can also be extended to create new configurations. The extend property specifies which definition to inherit from, while value contains additional or overridden properties.

For example, the following definition extends the red material by increasing its specular reflection and shininess: 

- define: shiny-red
  extend: red-material 
  value: 
    specular: 1 
    shininess: 300

The resulting material inherits all properties from red-material, with any properties specified in value added or overridden.

Important: Users do not need to specify the type of object a definition represents. The program determines its type based on the properties provided, as long as the definition is properly formatted.
The same applies when extending definitions. However, any properties added or overridden must be compatible with the type of the definition being extended. For example, extending a material definition allows you to add or override material properties, but not pattern or transform properties.
Tip: Definitions can be extended multiple times, allowing you to build upon existing configurations without modifying the original definition.

Definitions can be used with materials, patterns, and transforms. See their respective sections for examples of how definitions can be referenced and extended.
