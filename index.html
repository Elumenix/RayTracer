Documentation of how to use the code editor. Select a section below to explore its properties and examples.

This application uses YAML (YAML Ain't Markup Language), a human-readable data format, as input to the RayTracer. A scene consists of a list of objects and reusable definitions, including shapes, cameras, lights, materials, transforms, and patterns.

YAML lists of objects use hyphens (-) to start each entry, followed by indented key-value pairs that define its properties. Each hyphen represents a new entry, and properties belonging to that entry must be indented consistently.

Tip: Lists can also be written using square brackets to keep values on a single line. For example, color: [0, 0.2, 0] defines a list of three values. This notation is commonly used for properties such as colors, positions, and vectors.

Indentation also determines how properties are grouped together. Properties indented beneath another property belong to it, allowing you to define nested structures. This is particularly useful when defining materials, patterns, and transforms.

Property names must match those expected by the RayTracer. While YAML allows you to use different names, the RayTracer will only recognize supported properties.

Below is an example of a starter scene containing a camera, a light source, and a sphere: 


- add: camera
  width: 512
  height: 512
  field-of-view: 1.0472

- add: light
  at: [0, 5, 0]
  intensity: [1, 1, 1]

- add: sphere
  material:
  transform:
    - [translate, 0, 0, -3]
Important Note: A scene must contain exactly one camera in order to render.

The camera controls the viewpoint and resolution of the generated image. Every scene must contain exactly one camera.

The width, height, and field-of-view properties are required. All other properties are optional and will use their default values if omitted.

Properties
Property Description Required Default Valid Values / Constraints
width Image width in pixels Yes — Greater than 0
height Image height in pixels Yes — Greater than 0
field-of-view Field of view in radians Yes — Greater than 0 and less than 2π
reflection-depth Maximum number of ray bounces No 5 0 or greater
from Camera position No [0, 0, -5] 3D vector
to Look-at position No [0, 0, 0] 3D vector
up Camera up vector No [0, 1, 0] 3D vector
Performance Note: Image resolution (width and height) and reflection depth (reflection-depth) can significantly affect rendering time. Higher values generally result in longer render times.
Example

The following example defines a camera using only the required properties. All optional properties will use their default values. 

- add: camera
  width: 512
  height: 512
  field-of-view: 1.0472

You can also explicitly specify optional properties to customize the camera: 

- add: camera
  width: 512
  height: 512
  field-of-view: 1.0472
  from: [0, 0, -5]
  to: [0, 0, 0]
  up: [0, 1, 0]
Important: The up vector must be non-zero and must not be parallel to the camera's viewing direction (the direction from from to to). Otherwise, the camera orientation cannot be calculated.

A point light emits light in all directions from a single position in the scene. It illuminates objects and allows them to cast shadows.

Properties
Property Description Required Default Valid Values / Constraints
at Position of the light in world space Yes — 3D vector
intensity RGB light intensity (color) Yes — RGB vector
Tip: Adding at least one light to your scene is recommended. Without sufficient lighting, objects may appear very dark or not be visible at all.
Performance Note: Each additional light increases the amount of work required during rendering and may increase rendering time, particularly in complex scenes.
Important: Placing a light inside an object will likely prevent its light from escaping, regardless of the object's material. Position lights outside of objects to ensure their illumination reaches the rest of the scene.
Example

The following example defines a white light positioned at the origin: 

- add: light
  at: [0, 0, 0]
  intensity: [1, 1, 1]

The RayTracer supports three basic geometric shapes: planes, spheres, and cubes. All three use the same properties to define their appearance and positioning.

Shapes
  • Sphere: A three-dimensional ball.
  • Cube: A three-dimensional box with equal sides.
  • Plane: A flat, infinite surface.
Properties
Property Description Required Default Valid Values / Constraints
material Defines the surface appearance Yes (empty = default) Default material Material definition
transform Defines the shape's position, orientation, and scale Yes (empty = default) Identity transform Transform definition
Tip: Materials and transforms have their own properties and can be customized independently. See the Materials and Transforms sections for more information.
Example

The following example creates a red sphere and moves it three units along the negative Z-axis: 

- add: sphere
  material:
    color: [1, 0, 0]
  transform:
    - [translate, 0, 0, -3]

Materials determine how an object's surface interacts with light.

Property Default Description
color [1,1,1] Base RGB color
diffuse 0.9 Matte scattering
ambient 0.1 Background illumination
specular 0.9 Highlight brightness
shininess 200 Highlight sharpness
reflective 0 Reflectivity
transparency 0 Transparency
refractive-index 1 Light refraction
pattern None Surface pattern 
material:
  color: [1, 1, 1]
  diffuse: 0.1
  shininess: 300
  reflective: 0.9
  transparency: 0.9
  refractive-index: 1.5

RGB values must be between 0 and 1.

Patterns replace a material's solid color with a procedural surface design.

  • checkers - Checkerboard
  • stripes - Alternating stripes
  • gradient - Color gradient
  • ring - Concentric rings
  • radial - Radial pattern
  • blend - Blended colors/patterns
  • perturb - Randomized distortion
material:
  pattern:
    type: stripes
    colors:
      - [0, 0, 0]
      - [1, 1, 1]
Pattern Properties
  • type: Pattern type.
  • colors: Colors or child patterns.
  • seed: Random seed for perturb.
  • strength: Perturbation strength.
  • transform: Pattern positioning.
Standard patterns require exactly two colors. Perturb patterns require exactly one.

Transforms control the position, rotation, and scale of an object.

Operation Format
Translate [translate, x, y, z]
Scale [scale, x, y, z]
Rotate X [rotate-x, radians]
Rotate Y [rotate-y, radians]
Rotate Z [rotate-z, radians]
Shear [shear, xy, xz, yx, yz, zx, zy] 
transform:
  - [scale, 2, 2, 2]
  - [rotate-y, 0.7854]
  - [translate, 0, 1, -3]

Rotation values are specified in radians.

Define reusable materials, patterns, or transforms to avoid repeating configurations.

Define
- define: red-material
  value:
    color: [1, 0, 0]
    diffuse: 0.9
Use a definition
- add: sphere
  material: red-material
  transform:
    - [translate, 0, 0, -3]
Extend
- define: shiny-red
  extend: red-material
  value:
    specular: 1
    shininess: 300
  • define: New definition name.
  • extend: Existing definition to inherit from (optional).
  • value: Material, pattern, or transform configuration.
